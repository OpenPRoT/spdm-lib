    Add SPDM HEARTBEAT (0xE8) / HEARTBEAT_ACK (0x68) support to the Caliptra
    MCU Rust SPDM responder, together with the complete liveness mechanism the
    command exists for: HeartbeatPeriod advertisement, a per-session watchdog,
    keep-alive on session traffic, and automatic teardown. Closes the OCP 2.7
    SPDM-15 gap (HEARTBEAT_ACK required).
    
    Message layer (always compiled):
    - HEARTBEAT handler validates version + the 4-byte shape (reserved
      Param1/Param2 ignored per DSP0274) and returns HEARTBEAT_ACK. Phase-gated
      to an established secure session; an unsecured HEARTBEAT gets
      SessionRequired.
    
    Full liveness, behind off-by-default feature `spdm-set-heartbeat`
    (DSP0274 1.3.0 section 10.20):
    - KEY_EXCHANGE_RSP advertises a non-zero HeartbeatPeriod (default 3 s) iff
      both endpoints set HBEAT_CAP, else 0. The period is folded into both the
      partial and full builds so the transcript hash stays consistent.
    - A per-session watchdog is armed at 2x the period on FINISH_RSP
      transmission, only when the peer set HBEAT_CAP.
    - Any successfully handled secured command restarts the watchdog, so live
      traffic keeps the session open.
    - On watchdog expiry the run loop clears the session and erases its keys.
    - HBEAT_CAP is advertised only when the feature is enabled.
    
    The shipped default build is unchanged: no HBEAT_CAP is advertised and
    HeartbeatPeriod is 0 (the spec-legal "heartbeat not supported" behavior).
    
    Design notes:
    - The clock lives on the PAL trait (SpdmPalIoTransport) with an inert
      default (now_ms -> 0, sleep_ms pends forever), so host unit tests need no
      alarm capsule; the real PAL impl is alarm-capsule-backed (libtock Alarm
      via AsyncAlarm), compiled only under the feature.
    - The run loop races recv_request against the nearest session deadline with
      a minimal local two-future select (embassy-futures is not vendored),
      polling recv first so an arriving request wins a simultaneous timer.
    - The fake alarm capsule now tracks a virtual monotonic clock (command TIME
      reflects accumulated set_relative deltas) so tests can observe time move.
    
    Tests: 5 HEARTBEAT-handler cases, 7 liveness-watchdog cases (arm, touch,
    nearest-deadline, expiry, secured keep-alive, cap advertise/hide), and 2
    codec HeartbeatPeriod-encoding cases. Green with the feature both on and off.

    - Fold heartbeat_cap_flags() into a single cfg!() body instead of paired
      #[cfg]/#[cfg(not)] functions.
    - Factor the run-loop receive into a recv_next() free function so the
      feature-gated liveness-watchdog branching lives in one place. Taken over
      split borrows (pal shared, sessions mutable) rather than a &mut self

    feat(cmd-auth): [C] mcu_cmd_auth_improvement (#1848)
    
    * feat(cmd-auth): MCU-local asymmetric command authorization
    
    Authorize privileged MCU mailbox commands locally on the device using a hybrid
    ECDSA-P384 + ML-DSA-87 signature scheme, embedding only a hash of the vendor
    verification keys instead of the full keys.
    
    Design:
    - The device embeds only a 48-byte anchor = SHA-384(ecc_pub_x || ecc_pub_y ||
      mldsa_pub). The vendor public keys travel on the wire with each authorized
      command; the device recomputes the hash, matches the anchor, then verifies.
    - Freshness via a device-issued one-time 48-byte nonce that also travels on the
      wire (prod-debug-unlock idiom): the device compares the wire nonce to its
      stored challenge, then rebuilds the pre-image from the wire copy.
    - Authorization mirrors the prod-debug-unlock idiom: pre-image =
      cmd_id(BE,4) || cmd_body || nonce(48), signed as two digests of the same raw
      pre-image — ECDSA-P384 over SHA-384(pre-image) and ML-DSA-87 over
      SHA-512(pre-image).
    - Strict-AND, fail-closed verify: nonce == stored one-time challenge ->
      SHA-384(received pubkeys) == embedded anchor -> ECDSA -> ML-DSA; any failure
      returns AccessDenied.
    - Verification reuses the existing generic Caliptra ECDSA384_SIGNATURE_VERIFY
      and MLDSA87_SIGNATURE_VERIFY mailbox commands; no new Caliptra command.
    - Gates all eight mailbox-dispatched authorized commands (FE_PROG,
      PROVISION_VENDOR_PK_HASH, FUSE_READ/WRITE/LOCK_PARTITION,
      INCREASE_CALIPTRA_MIN_SVN, REVOKE_VENDOR_PUB_KEY/PK_HASH) over the MCU mailbox
      and SPDM/VDM transports.
    
    Sizing: authorized requests carry the traveling public keys (~7.5 KiB), so the
    mailbox scratch pool is raised 12 KiB -> 16 KiB to hold the request buffer, the
    response buffer, and the SVN/revoke handlers' nested FW_INFO allocation
    concurrently; otherwise fw_info fails with OUT_OF_MEMORY after authorization.
    
    Integration boot: boot the MCU runtime the SoC manifest digested rather than
    injecting a separately compiled runtime, which would not match the bundle
    manifest under CPTRA_FIRMWARE_BUNDLE (RUNTIME_DIGEST_MISMATCH).
    
    Tests: MCU-local gate tests (G1 positives per command, G2 anchor, G3 nonce, G4
    tampered body, G5 strict-AND), anchor key-substitution and replay isolation, and
    a wire-size KAT.

    Comment-only touch to re-trigger CI.
    
    * refactor(cmd-auth): centralize the nonce width + verify both signature legs
    
    Address the same review feedback applied to the sibling nonce-48 PR: use a
    single source of truth for the authorized-command challenge/nonce width and

    Addresses two review comments on the authorized-command decoder.
    
    1. Replace the manual per-field slice walk with a zerocopy struct.
    
       The signatures-last reorder made the walk five `req.get(off..off + N)` steps
       with four `off +=` bookkeeping lines. Introduce
    
         #[repr(C)] struct AuthorizationBlock {
             nonce[48] | ecc_pub_x[48] | ecc_pub_y[48] | mldsa_pub[2592] | sig
         }
    
       and parse it in one call. All fields are u8 arrays, so #[repr(C)] adds no
       padding and alignment is 1; a cast can only fail on length.
    
       Uses ref_from_prefix, not ref_from_bytes or ref_from_suffix:
       - ref_from_bytes is exact-size and would newly reject frames with trailing
         bytes, which the previous walk accepted.
       - ref_from_suffix anchors to the end of the slice, so trailing bytes would
         silently shift the window and misparse the nonce and keys.

       at cmd_len (which includes MailboxReqHeader) while cmd_body starts after that
       header. The struct describes only the fixed tail, so neither base moves.

       five per-field offset_of!. Per-field offsets matter because a size-only
       assert passes for any field permutation, so it would not catch a reorder.
       This matches the asserts already guarding the two sibling definitions of the
       same wire layout, FeProgVdmReq and FeProgRequest.
    
    2. verify_signatures now calls the existing take_challenge() trait method
       instead of inlining CHALLENGE.lock(|state| state.borrow_mut().take()).
       Byte-identical body, same consumption point before the nonce comparison, and
       it gives the previously uncalled trait method its only caller.
    
    Both changes are behaviour-preserving. Verified: cargo build (the new asserts
    are the layout proof), cargo fmt --check, cargo clippy, and test_cmd_auth_asym
    10/10 pass on a firmware bundle rebuilt from this source.
